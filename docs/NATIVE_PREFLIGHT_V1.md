# Native dataset preflight and optional steward assessment, version 1

`observations.native_preflight` inspects a self-contained dataset representation without loading a model or scoring predictions. `NATIVE_DATASET_SCHEMA_V1.json` specifies required fields, types, units, native measurements, source-order input components, timing, participant linkage, provenance and refusal conditions. It is an acquisition specification, not evidence that a cohort satisfies it.

The result separates metadata, structural compatibility, measurement authority, participant independence, dataset-use authorization, result-generation authorization and result-disclosure authorization. Metadata-only mode reads the dataset header without inspecting observations. Full validation checks linked participant splits and alias cycles; reused assessment/trial/query/input IDs; copied and near-copy query vectors; exact query/assessment/participant associations; target windows and units; three valid trial means and positive explicit system mass; complete history and the two latest qualifying baselines; the source 39-feature projection and four history tokens; actual origin-known exposure plans; origin-keyed routine state; frozen training preprocessing; and the independently reconstructed five-value basis when any candidate 6–8 is declared. Every origin must have H72 and D7 with both native targets.

Review decisions require their scope, complete dataset-manifest digest, references, reviewer and approval state to match SHA-256 pins supplied separately through `trusted_reviews`. Neither a matching pin, a valid schema, a caller-supplied approval nor the synthetic label establishes real-world truth. External source authentication, alias completeness, complete assessment history, actual collection times, device calibration, phase-detection validity, consent, rights and disclosure decisions still require qualified reviewers. Review records bind every dataset value and identity by canonical JSON SHA-256 excluding the review records themselves. Altering any source, identity, preprocessing, observation or plan invalidates the old reviewed manifest. Tied qualifying baseline timestamps are refused for adjudication, and a trial cannot be silently dropped from a four-trial set to manufacture a three-trial criterion. Assessment values cannot be declared available before measurement. The original source accepts event timestamps; this validator does not invent an empirical event detector or canonical crosswalk.

**Empirical execution remains blocked**, even if every structural and declared review check passes. `eligible=True` applies only to explicitly synthetic engineering admission with separately pinned synthetic reviews. It is not authorization for a real cohort. No dataset record can enable empirical scoring through this module.

The input representation requires each selected trial’s calibrated force/time samples, explicit gravity, supplied onset/takeoff events, SOP/calibration pins, relative/native trial summaries and pinned measurement provenance. Ordered events inside signal support are integrated with the source constructor and must reproduce both native trial summaries before the exact three-trial mean is admitted. These arithmetic checks cannot prove that supplied signals, event timestamps or calibration records correspond to real measurements. The additive check is a new native-source-contract check, not proof of an exact historical stored-value transform. Missing fields, unsupported mechanics, unresolved support and missingness are refused. No input values, durations, history or labels are imputed. Near-copy checks use the same horizon and distinct origins with raw vectors within absolute tolerance `1e-8`, including shifted dataset-clock origins; this is conservative screening requiring adjudication, not proof of plagiarism or exhaustive duplicate detection.

## Local steward tool

The optional command runs entirely in the future authorized steward's own environment:

```console
python -m cmj_recovery_dynamics.observations.native_preflight INPUT.json
```

It produces only aggregate counts within declared test groups for participants with sufficient history, participants with the baseline pair, queries in each target window, complete native targets, common M0–M5 input coverage, M6–M8 basis coverage, and structurally potentially eligible groups. It emits no identities, labels, individual refusals, input excerpts or file paths, including on malformed input. Component coverage is counted separately; potentially eligible groups are conservatively zero unless the entire submitted dataset passes structural inspection. These are compatibility counts, not numbers authorized for evaluation.

The complete count vector is suppressed if any nonzero count or its complement is below five. Participant counts use the declared test-group denominator and query counts use the test-query denominator. Training and validation groups are excluded from every released count, avoiding disclosure of small training/validation complements. The implementation permits a larger threshold but refuses one below five. Output always requires steward-controlled disclosure review. Threshold suppression cannot defeat repeated/adaptive queries or cross-run differencing by itself: the steward must approve a fixed population, one release and any linkage to other reports. Do not publish arbitrary repeated outputs. Small-group suppression is an engineering default, not a claim of legal or statistical anonymity.

`synthetic_preflight_fixture()` constructs an explicitly invented labeled engineering fixture; `synthetic_trusted_reviews()` contains invented test review pins. They must never be presented as an authentic historical experiment, a human cohort, scientific approvals or evidence of predictive validity. Qualification deliberately mutates identities, units, targets, windows, trials, history availability, plans, basis, review decisions and preprocessing to demonstrate refusal. No external data or private historical labels are used.
